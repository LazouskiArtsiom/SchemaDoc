# SchemaDoc — project guide for Claude

A self-contained **Blazor Server (.NET 9, C#)** desktop tool for exploring, documenting,
diffing, and migrating database schemas. It runs locally, opens in the browser, and ships
as a single self-contained Windows exe. Latest release: **v1.6.0**.

Supported databases: **SQL Server** (incl. Azure SQL Database), **PostgreSQL**, **MySQL**,
**Azure Cosmos DB**. Deep features (migration script generation, stored-procedure/function
extraction, dependency tracking) are **SQL Server–only**; the other providers get
documentation/exploration and basic extraction.

## Solution layout

`SchemaDoc.sln` → five projects under `src/` plus tests under `tests/`.

| Project | Role |
|---|---|
| `SchemaDoc.Core` | Provider-agnostic models (records), `SchemaDiffService`, `MermaidGenerator`, migration generator (`Services/Migration/`: `MigrationScriptGenerator`, `MigrationAction`, `ISqlDialect` + `SqlServerDialect`/`PostgreSqlDialect`/`MySqlDialect`), interfaces. **No external deps.** |
| `SchemaDoc.Extraction` | One `ISchemaExtractor` per provider (`SqlServerExtractor`, `PostgreSqlExtractor`, `MySqlExtractor`, `CosmosDbExtractor`) using **Dapper**; `ExtractorFactory`. |
| `SchemaDoc.Infrastructure` | EF Core + **SQLite** app DB (`AppDbContext`, `Data/Migrations/`), repositories, `Security/ConnectionStringProtector` (DPAPI). |
| `SchemaDoc.Export` | `PdfExporter` (QuestPDF), `HtmlExporter`, `DrawioExporter`. |
| `SchemaDoc.Web` | Blazor Server UI. Pages in `Components/Pages`, shared components in `Components/Shared`, JS interop in `wwwroot/js`, app services in `Services/`. |

App state (connections, snapshots, annotations, tags) lives in a **SQLite** DB at
`%LocalAppData%/SchemaDoc/schemadoc.db`, auto-migrated on startup (`Program.cs`).

## Build / run / test

```bash
# Build (stop the preview server first if it's running — the app locks SchemaDoc.Web.dll)
dotnet build src/SchemaDoc.Web/SchemaDoc.Web.csproj -c Debug

# Run from source (Development profile → http://localhost:5096, no auto-open)
dotnet run --project src/SchemaDoc.Web/SchemaDoc.Web.csproj
# Released exe binds http://localhost:5000 and auto-opens the browser.

# Tests
dotnet test tests/SchemaDoc.Extraction.Tests/SchemaDoc.Extraction.Tests.csproj
```

- **Most work needs a running local SQL Server** (`localhost`, Windows auth). If the DB list
  is empty, the `MSSQLSERVER` service may be stopped — start it (`net start MSSQLSERVER`, elevated).
- The test suite mixes **DB-free unit tests** (`IndexScriptTests`) with **integration tests**
  that create/drop a real `SchemaDoc_MigrationTest` DB and apply generated migration scripts,
  asserting zero residual diff. They require local SQL Server databases seeded from
  `scripts/*.sql` (notably `SchemaDoc_Prod` / `SchemaDoc_Staging` / `SchemaDoc_Dev`, plus
  `HRSystemDB` for the PDF smoke test). `tests/SchemaDoc.Core.Tests` is an empty stub.
- **EF migrations:** `dotnet ef migrations add <Name> --project src/SchemaDoc.Infrastructure --startup-project src/SchemaDoc.Web`. Keep model changes **additive/nullable** so old snapshot JSON still deserializes.

## Key invariants & conventions (non-obvious — read before changing)

- **Connections are server-level.** A saved connection = one server; the database is *not* in
  the stored connection string. Each extractor implements `SwitchDatabase(cs, db)` to reroute
  per database. `SchemaLoaderService.LoadSchemaAsync` always live-extracts (it does **not**
  read snapshots as a cache).
- **Tags:** `SavedConnection.Tag`/`TagColor` is the server default (Tag normalised to `""` so the
  unique index on `(Name, Tag)` works). `DatabaseTag` rows are per-database overrides; the sidebar
  and Home compute the effective tag (override or inherited).
- **Snapshots:** persisted as JSON of `DatabaseSchema`. **Named** snapshots are durable (never
  auto-rotate); **unnamed** ones auto-rotate at a cap (10) per `(connection, database)`. The ⭐
  marks the **freshest** snapshot per database — ordering is `ExtractedAt DESC, Id DESC`
  (the `Id` tie-breaker keeps "freshest" deterministic). Per-database snapshots render on **Home**;
  server-wide (grouped by database) on **`/server-snapshots`**, which also has a
  "Snapshot all databases" button.
- **Diff (`SchemaDiffService`):** `IsAutoGeneratedName` recognises SQL Server `PK__T__HEX`, PG
  `_pkey`/`_fkey`, Oracle `SYS_C…` and matches such constraints/FKs **structurally** so cosmetic
  name churn isn't reported. `NormalizeSqlText` strips comments/whitespace/**trailing semicolons**
  before comparing routine/trigger bodies. Diff covers tables, columns, PK/unique/check
  constraints, indexes, FKs, triggers, procedures, and functions.
- **Migration generator:** `BuildActions` returns a togglable `List<MigrationAction>`; the UI
  filters via checkboxes; `AssembleScript` orders by `MigrationActionType` enum value
  (drops 5–80, creates 110–210 — **functions before procedures**), wraps in a dialect transaction
  (null for MySQL: DDL auto-commits), and emits an **early `GO` before `CREATE TRIGGER/PROCEDURE/FUNCTION`**
  on SQL Server (so leading comments don't get baked into `sys.sql_modules`). `DialectFor` throws
  `NotSupportedException` for Cosmos; proc/function DDL throws for PG/MySQL (SQL Server only).
  `CreateIndex` appends `WITH (ONLINE = ON)` **only for plain rowstore indexes** (never columnstore/XML/
  spatial/hash) — requires SQL Server Enterprise or Azure SQL (errors on Standard/Express, kept per product decision).
- **SQL Server `ListDatabasesAsync` is Azure-aware:** it queries `sys.databases` from `master` and
  bypasses the `HAS_DBACCESS` filter when `EngineEdition = 5` (Azure SQL Database), where that
  function returns 0 for sibling DBs. Errors **propagate** (no swallowing) so the UI shows the real cause.
- **Schema-read command timeout is 300s** (`SchemaReadTimeoutSeconds` in `SqlServerExtractor`).
- **Entra/MFA auth providers are registered explicitly in `Program.cs`** because the module-initializer
  registration gets trimmed out of the single-file publish. Auth methods in the SQL Server connection
  form: SQL login, Windows, and Entra Interactive(MFA)/Password/Service Principal/Integrated/Managed
  Identity/Default.
- **Extraction is read-only.** It only reads catalog metadata; migration scripts are generated as
  text for the user to review and run — the app never executes DDL against target databases.
- Models are C# **records**; Dapper raw DTOs are plain classes (`Raw*`). Match the existing file's
  comment density and idioms.

## Release & git workflow

- CI is **release-only**: `.github/workflows/release.yml` triggers on pushing a `v*` **tag**
  (not on commits/PRs). It builds a self-contained single-file `win-x64` exe and publishes a
  GitHub release with `SchemaDoc-win-x64.zip`. There is no `workflow_dispatch`.
- Cutting a release: commit to `main`, then `git tag vX.Y.Z && git push origin vX.Y.Z`.
- **Only commit/push/tag when the user explicitly asks.** End commit messages with the
  `Co-Authored-By` trailer. The migration/EF migration for any new entity fields must be committed
  with the change (the app auto-migrates on first run for upgraders).

## Notes

- `scripts/*.sql` seed the local demo/test databases. `.claude/launch.json` defines the preview
  server (port 5096). `docs/index.html` + `netlify.toml` are an out-of-scope landing page.
- When verifying UI changes, run the app and drive it in the browser rather than asking the user to check.
